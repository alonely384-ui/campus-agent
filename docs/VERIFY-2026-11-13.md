## 四、交叉检验三：分类结果独立复核（**发现并修复 1 个真缺陷**）

**方法**：从 `data/catalog.json` + `data/meta/structures.json` 现算，不读任何缓存。

### 4.1 发现缺陷

首跑实测状态分布为 `classified 38 / pending 2`，与既有结论「classified 38 / manual 1 / pending 1」不符，多出 1 篇「待归类」。

根因定位：`app/topics.py` 的 `assign_all()` 只从 `item["file"]` 取文件名，而 `MANUAL_OVERRIDES` 的键是 `"1706.03762v1_img.pdf"`。调用方（`app/main.py`、测试）传进来的键是 `filename`，于是 `MANUAL_OVERRIDES.get("")` 恒为空串，**人工兜底被静默吞掉**。

验证命令与输出：

```
$ python -c "..."
MANUAL_OVERRIDES = {'1706.03762v1_img.pdf': 'Transformer'}
classify with manual    = manual 模型架构 Transformer 人工核对后指定 manual
classify without manual = pending 待归类 标题与摘要都没有足够具体的分类证据
```

即 `classify()` 本身是对的，是 `assign_all()` 没把文件名传进去。

### 4.2 修复

`app/topics.py` 的 `assign_all()` 改为同时接受两种键名：

```python
filename = str(item.get("file") or item.get("filename") or "")
...
manual=MANUAL_OVERRIDES.get(filename, ""),
```

### 7.4 关于一次偶发失败（如实记录）

回归过程中 `tests/test_event_loop_blocking.py::test_papers_topics_does_not_block_event_loop` 失败过 1 次。处理过程：

1. 单独跑该用例 → 通过
2. 写 `scripts/_diag_flaky.py` 对 3 个时序用例各连跑 6 次 → **各 6/6 通过**
3. 再连跑 3 次全量 → **801 / 801 / 801 全通过**

归因：那次失败发生在其 concurrently 运行的子代理审计（占满 CPU）期间，属机器负载导致的时序抖动，非代码缺陷。

即便如此仍做了加固：`_assert_loop_free()` 在原有 `during >= expected / 3` 之后补了一条下界断言，用来把「进程被系统挂起」与「事件循环被阻塞」区分开：

```python
assert during >= 3, (
    f"{slow_name} 执行期间心跳只跳了 {during} 拍，连 3 拍都不到——"
    f"更像是测试进程被挂起或机器过载，而不是事件循环被阻塞，请重跑确认"
)
```

`pytest tests/test_event_loop_blocking.py -q` → **18 passed**。

## 十、已知风险与未解决项

1. **社区划分未通过随机基线**。口径 A（全 1 权重）实测 Q = 0.1147 / 0.0792，随机图均值更高，`p = 0.285 / 0.865`。因此功能定位已统一降级为「引用关系簇」，所有用户可见文案与技术文档均不再宣称它代表研究子领域。
2. **附录正文误抽取已修但有残留**。`_reference_stop_index` 依赖 PDF 结构证据（标题字号 ≥ 正文字号 × 1.10），对 `1910.02054v3`（ZeRO，附录正文与正文字号同为 10.0pt）无法识别，其附录内容仍计入条目。
3. **空标题条目仍在**。实测：41 条索引记录中 40 篇有参考文献抽取结果，**空标题条目共 117 条，分布在 24 篇论文里**（最多的是 `2305.13048v2.pdf` 19 条、`2406.14491v2.pdf` 17 条、`2211.05100v4.pdf` 13 条）。它们不是参考文献而是误抽正文，计入 `entries_total` 后会抬高 `unmatched`。
4. **review 队列 1295 条中 1272 条是 `arxiv_absent`**（引用声明的 arXiv 编号不在库内），人工核验价值低；真正需要人看的只有 `review_title_fuzzy` 23 条。
5. **技术文档恰好 30 页**，无增补余量；后续任何内容增加都需先压缩别处。
6. **`_looks_like_heading` 的潜伏误判路径**：单作者缩写 + 大写标题的文献条目，若其字号恰好 ≥ 正文 × 1.10，会连带其后所有条目被整体丢弃。当前 41 篇语料未触发，但换一批 PDF 可能触发。未在本轮修复（改动风险高于收益，且用户本轮指定范围不含此项）。
7. **`_fuzzy_key` 相关注释与实现语义不符**（`norm_title` 删空格、`_fuzzy_key` 保留空格），不影响运行结果，但会误导维护者。
8. **本轮未做**：ZeRO 附录识别、空标题清理、review 队列分层、深色模式。
