## 第 1 节：一个请求的一生

**一句话**：你在网页打一句话，它穿过 4 层，才到“翻论文”那一步。

**路径**

```
手机浏览器
  → uvicorn（把 HTTP 变成 Python 函数调用）
    → FastAPI 路由 /chat
      → Pydantic 校验（太长太短直接退回）
        → agent 循环（调模型、查论文）
          → 拼回答返回
```

**为什么**：分层是为了出错时能定位。422 是第 3 层挡下的，500 是第 5 层炸的。

**自测**：输入框什么都不填点发送，会返回哪个状态码？

## 第 2 节：四层地图

**一句话**：这个项目只有四层，记住层名就能找到代码。

```
界面层  web/index.html
对话层  app/agent.py       ← 调模型、拼 prompt
检索层  app/rag/pipeline.py ← 切块、索引、召回、重排
数据层  app/papers.py + data/
```

**判断你在看哪层**：看它“输入是什么、输出是什么”。
输出 HTML → 界面；输出回答文本 → 对话；输出一堆片段 → 检索；输出文件 → 数据。

**自测**：`split_text()` 属于哪层？

## 第 3 节：/chat 为什么先校验再干活

**一句话**：参数不合法，绝不花你 API 的钱。

**三行**

```python
message: str = Field(..., min_length=1)
history: list[dict] = Field(default_factory=list)
source: str | None = None
```

**为什么**：`Field` 是声明式校验，FastAPI 在调用函数体**之前**执行。
空字符串 → `422 string_too_short`，函数体一行都没跑。

**自测**：`422` 和 `500` 分别是谁的锅？

## 第 4 节：检索怎么变成 prompt

**一句话**：检索结果是“资料”，模型只准依据资料回答。

**关键函数**：`_rag_context_with_evidence()`

它做四件事：

1. 把问题翻成英文检索词（第 5 节）
2. 召回片段，每条带 `source` 和 `page`
3. 拼成一段“参考资料”系统消息
4. 同时返回 `evidence`（证据卡片用的）

**为什么**：光给片段模型可能乱引；必须同时给“文件名 + 页码”并要求它照抄。

**自测**：证据卡片的数据是哪一步产生的？

---

## 第 5 节：为什么要先翻成英文

**一句话**：向量模型只懂英文，中文直接查会跑偏。

**三行**

```python
if has_chinese(question):
    query = await _search_query(question)  # 翻译
```

**为什么**：`all-MiniLM-L6-v2` 是英文模型。
中文“训练用了多少块显卡”和英文 `GPUs` 在它的向量空间里不是邻居。

**注意**：翻译结果会写进 `data/chroma/query_cache.json`。
同一句问第二次不再调模型 —— 这是为了“同一问题每次答案一致”。

**自测**：为什么翻译要缓存，不缓存会怎样？

## 第 6 节：切块为什么是 300 字 + 10% 重叠

**一句话**：太长稀释，太短断句，300 字是测出来的。

**三行**

```python
chunk_size = 300
overlap = int(chunk_size * 0.1)  # 30 字
```

**为什么**：

- 太长：一个块里混进好几个主题，排名被平均掉
- 太短：一句话被切成两半，答案缺一半
- 重叠：防止“答案正好卡在切口”

**数字**：实测 150/200/300 命中率相同，300 块数最少，所以选 300。

**自测**：重叠 30 字解决的是什么问题？

---

## 第 7 节：哈希向量是什么

**一句话**：把文字切成两字一片，丢进 1024 个抽屉里数数。

**三行**

```python
gram = clean[i:i+2]              # 两字一片
idx = crc32(gram) % 1024         # 落到哪个抽屉
vec[idx] += 1.0                  # 计数
```

**为什么用 `crc32` 不用 `hash()`**：
`hash()` 每次启动结果不同，索引和查询会算不到一块。

**它的弱点**：只认字面。“助学金”和“困难认定”字不同，它认不出来 —— 所以还要稠密向量。

**自测**：为什么同一个词每次必须落到同一个抽屉？

---

## 第 8 节：三路召回 + RRF

**一句话**：三个评委各自排名，按名次合分，不看各自给的分数。

**三行**

```python
score += weight / (60 + rank + 1)
# 稠密 2.0 / BM25 1.0 / 哈希 0.5
```

**为什么**：三路分数尺度不同（余弦 0~1、BM25 可能 20+），
直接加会被 BM25 吞掉。RRF 只看“排第几”，天然对齐。

**自测**：为什么不能把三路分数直接相加？

---

## 第 9 节：重排放在最后

**一句话**：先用便宜的召回 50 条，再用贵的模型精挑 4 条。

**流程**

```
召回 50 条（向量 + BM25 + 哈希）
  → RRF 融合
    → 重排模型（问题+片段成对打分）
      → 取前 4 条进 prompt
```

**为什么**：召回模型是“各算各的”，重排模型是“问题片段一起看”，精度高但慢。
所以重排只处理 15 条候选，不处理全库。

**数字**：开重排 R@1 从 28/38 提到 30/38，延迟 +245ms。

**自测**：为什么不直接用重排模型跑全库？

---

## 第 10 节：查重 0.873 怎么来

**一句话**：两篇都切成两字片，看重合比例。

**三行**

```python
grams_a = set(grams(text_a))
grams_b = set(grams(text_b))
jaccard = len(a & b) / len(a | b)
```

**为什么**：v1 和 v7 是同一篇论文的两个版本，文字 87% 重合；
换成“复制粘贴改标题”也能识别。

**注意**：只提示、不拦截。科研要留版本。

**自测**：为什么去重是“提示”不是“拒绝上传”？

## 第 11 节：表格计数为什么能答对

**一句话**：答案藏在表格第 8 页，但检索从来不给第 8 页 —— 所以单独补。

**三行**

```python
if _is_count_question(question):     # 问“几个/几种”
    pages = _table_pages(source, q)  # 找最像答案的表格页
```

**为什么**：

- 表格页本身不像“一段话”，向量召回排不上去
- 表题 `Table 2.1: Sizes, architectures...` 命中“规模”关键词 → +20 分
- 补进上下文后，模型逐行数出 8 个

**自测**：为什么只扫“表题行”，不扫整页？

## 第 12 节：七个必须记住的数字

| 数字 | 含义 |
|---|---|
| 39 | 入库论文篇数 |
| 25995 | 索引块数 |
| 300 / 30 | 每块字数 / 重叠字数 |

## 答案

1. Pydantic 校验层（在函数体之前）
2. `_rag_context_with_evidence()`
3. 向量模型是英文的，中文查询召不回正确页
4. 答案正好卡在切口时被切断
5. `hash()` 每次启动结果不同，索引对不上
6. 三路分数尺度不同，直接相加会被大的吞掉；RRF 只看名次
7. 15 条；重排慢，全库跑不动
8. 0.873；科研要保留论文版本
9. 表题里出现 sizes/parameters 等词时加分
10. 25995 块 / top1 30/38 / 81 个测试
