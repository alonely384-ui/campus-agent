### 3.2 扫描件为什么算「没过」

`scripts/borrow_sections.py` 开头写得很直白：

> 背景：`1706.03762v1_img.pdf` 这类扫描件没有文本层，正则再准也抽不到标题。
> 但只要库里还有同一篇论文的可解析版本（`1706.03762v7.pdf`），它的章节树就是
> 同一份目录——直接借过来，页码按捐赠者那份算（扫描版页码可能有偏移，属已知误差）。

`app/reader.py:109-111` 也在前端注明来源：

```python
# 扫描件抽不出标题时，章节树是借用同一篇论文的文本版（页码按文本版算）；
# 前端据此在侧栏注明来源，别让人以为扫描件自己解析出了目录。
"sections_borrowed_from": str(meta.get("sections_borrowed_from") or ""),
```

**问题在于**：`check_112.py` 那句「章节 45/45 100%」把这个借用算进去了。如果评委只打开扫描件本身，
看到的是标题为空、作者为空、摘要为空、表格图表公式参考文献全空——**只有目录，而且是别人的目录**。

这正是本文要指出的核心：**覆盖率漂亮，但官方点名的那一篇自己不会解析。**

### 3.3 已排除的误报：书籍的「表格 0」不是缺陷

用到脚本逐页查了全书：

```
全书文字字符数: 1313319
含 'Table' 的页数: 0      ← 大写一个都没有
含 'table' 的页数: 76     ← 全是正文里的普通词
匹配 "[Tt]able\s+" 的次数: 69
  p11  ...this was a notable exception...
  p27  ...produce an interpretable description...
  p27  ...inevitable feature of human behavior...
  p30  ...inevitable that this book will be a constant work in progress...
  p67  ...Binomial coeﬀicient attributable to the last layer...
```

69 处全部是 `notable` / `interpretable` / `inevitable` / `accountable` / `attributable` / `target`
这类**正文单词**，没有一处是表题。**这本书本身就没有表格，表格 0 是正确结果。**

### 3.4 扫描件的根因：OCR 结果已经躺在磁盘上，解析器不读

```

          avaswani@google.com'

```


**字已经 OCR 出来了（标题、作者、单位、邮箱都在里面），只是 `structure.py` 从来不读这份缓存。**
RAG 那条线是读的（`app/rag/pipeline.py:393`、`:1134`），只有结构解析这一侧漏了。

这一项是「差一步」，不是「做不到」。
